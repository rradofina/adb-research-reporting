# The four tiers

A program at **Hypothesis** is an idea with a registered claim sentence.
It may have a literature scan, a draft method, even a working pipeline
on a single fixture DMC. It does not yet have a screening artifact. The
lab considers it "interesting enough to register, not yet far enough to
trust."

A program at **Prepared Pipeline** has a committed script that, given a
clean clone, runs end-to-end. It produces output. The output is not yet
empirically claimed — that is the next gate. Prepared Pipeline says:
"the engineering exists; nothing has been concluded."

A program at **Screening Result** has produced an empirical artifact.
The output is preliminary; it is triage. The Screening-Result label
prohibits the program from being framed as if its output were a finding.
A screening result invites further work, not policy action.

A program at **finished for issue** has crossed the most stringent
current-issue gate. The literature is reviewed or synthesized for the
stated chain, the pre-registration was frozen before the pipeline ran,
the sensitivity suite at ±50% has been completed where applicable,
review objections have written responses, and the replication archive
is public. In the current §18 issue, some of those gate actions are
AI-first rather than human-final; a human-final upgrade requires the
named-reader review and owner-signed attestation chain. Finished for
issue does not mean "important." It means "the gates are satisfied for
the stated attestation chain."

# What the labels do not promise

The labels are not a quality ranking. A Hypothesis-tier program in a
critical-policy domain matters more than a finished current-issue program
in a marginal one. The gate is internal discipline, not external
importance.

The labels are not permanent. A program that loses its pre-registration
discipline — a result is silently edited after a pipeline run, or a
sensitivity failure is not addressed — is demoted, not paper-edited.
Demotion is a normal lab operation.

The labels are not a publication promise. A finished current-issue program
may sit at PR for months while the article itself is drafted, reviewed,
and submitted. The label commits the lab to the gate; it does not
commit a venue.

# Why caps

The lab caps work-in-progress at one human-final PR program and three
Screening-Result programs at any time. The cap is not arbitrary. The
sensitivity suite, the systematic literature review, the external
red-team round-trip — each of these is multi-week work. Pushing two
programs to human-final PR in parallel halves the attention each
receives.

Under §18 AI-first operating mode, that cap is suspended for the current
issue because the site is explicitly labeling the AI-first chain. The
cap returns for human-final work.

The cap also protects against an institutional failure mode the lab is
explicit about: the pull to publish-and-move-on. The cap forces the
question "is this program closer than the others?" before the gate
work begins, and the question "is anything still load-bearing about
this program's headline?" before the article goes out.

# What labels you will see

The reporting site shows a chip beside each program's title. The chip
encodes the current label and should be read with the attestation chain.
An AI-first label is not hidden; it is part of the claim.

As of the 2026-07-07 current-issue closure, the public issue classifies
all eighteen topics: seven finished for the current issue, eight
screening-only, one Program Prospectus, one Prepared Pipeline, and one
Hypothesis. Those are reader-facing issue labels, not human-final venue
claims.

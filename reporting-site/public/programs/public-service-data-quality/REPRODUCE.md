# PSDQ reproducibility guide

Last updated: 2026-06-19.

This guide is the single runbook for reproducing the current
`public-service-data-quality` package. It connects the source caches, pipeline
scripts, generated outputs, public evidence sync, and gates. The broader
research-factory process lives in `research/factory.md`; the current status and
blockers live in `research/STATUS.md`. The owner/source handoff and completed
PSA manual-download record live in `SOURCE-ACTION.md`.

## Current reproducibility status

The current PSDQ package is reproducible from the scripts and existing public
caches in this repository. The previous PSA SAE source-access blocker was
resolved on 2026-05-05 when the owner manually downloaded the official
workbook and Codex seeded the canonical cache.

- Philippines and Bangladesh ADM1 registry-vs-OSM outputs are generated from
  cached registry pages and the existing `luminosity-gap` access-services OSM
  artifact.
- Bangladesh Open Buildings facility-buffer, upazila exposure, and road-context
  outputs are generated by the Python drivers in `scripts/`.
- The Bangladesh source-disagreement L3 strata artifact is a no-network
  packaging pass over the generated exposure and road-context outputs.
- The Bangladesh facility-validation sample is a no-network design pass over
  the L3 strata, exposure-ranked table, and DGHS facility-coordinate extract.
  It produces a blank coding sheet, not validation outcomes.
- The Bangladesh facility-validation coded screen is a no-network public-source
  screen over the blank coding sheet, the existing all-Bangladesh OSM
  health-feature cache, and geoBoundaries ADM3. It is automated triage, not
  manual validation.
- The Bangladesh AI public-source review ledger is a no-network second pass
  over the coded screen and OSM candidate table. It separates flagged rows into
  public-map-gap, coordinate-repair, name/type-resolution, and nearby-OSM
  workstreams. It is not human validation.
- The Bangladesh coordinate-repair triage is a no-network pass over the
  coordinate-repair subset, public geoBoundaries ADM3, cached OSM health
  features, and cached DGHS public rows. It separates missing coordinates,
  reused coordinates, wrong-admin coordinates, and public-boundary mismatches.
  It is not human validation.
- The Bangladesh public-map-gap triage is a no-network pass over the
  public-map-gap subset after coordinate screening. It keeps all 40 rows open
  while separating duplicate-coordinate, same-upazila name-signal,
  buffer-sensitivity, zero-OSM-upazila, OSM-present-not-at-facility, and
  no-nearby-OSM lanes. It is not human validation.
- The Bangladesh public-map-gap row-evidence pass is a no-network pass over the
  public-map-gap triage CSV/JSON. It attaches DGHS source notes, public profile
  URLs, OSM coordinate-inspection URLs, OSM feature or absence notes, and
  keep-open reviewer actions for all 40 map-gap rows. It is not row closure or
  human validation.
- The Bangladesh targeted public-map inspection pass is a no-network pass over
  the row-evidence CSV/JSON, the pinned all-Bangladesh OSM health-feature
  cache, and public ADM3 boundaries. It builds the first inspection queue and
  keeps all 40 rows open.
- The Bangladesh first-row public-source confirmation pass retrieves public
  DGHS profile pages and public OSM API feature records for the first 12
  targeted inspection rows. It records retrieval status and keeps all 12 rows
  open. It is not human validation.
- The Bangladesh targeted-row public-source confirmation pass retrieves public
  DGHS profile pages and public OSM API feature records for all 40 targeted
  inspection rows. It records retrieval status and keeps all 40 rows open. It
  is not human validation.
- The Bangladesh public-source decision ledger is a no-network pass over the
  targeted-row confirmation packet. It selects possible same-facility,
  source-repair, and priority-1 name-conflict rows for reviewer decisions while
  keeping all rows open. It is not human validation.
- The Bangladesh possible same-facility review is a no-network pass over the
  decision ledger and targeted-row confirmation packet. It isolates the three
  possible same-facility public-map candidates, carries forward name-score and
  distance evidence, and keeps closure/reclassification blocked. It is not
  human validation.
- The Bangladesh priority name-conflict review is a no-network pass over the
  decision ledger and targeted-row confirmation packet. It isolates the nine
  priority-1 name-conflict candidates, carries forward name-score, distance,
  admin-place-name, and alias-source evidence, and keeps all rows open. It is
  not human validation.
- The Bangladesh lower-priority name-conflict spot check is a no-network pass
  over the targeted-row confirmation packet and decision-ledger summary. It
  isolates the six deferred lower-priority name-conflict candidates, carries
  forward repeated-candidate, name-score, distance, and alias-source evidence,
  and keeps all rows open. It is not human validation.
- The Bangladesh zero-OSM upazila observability review is a no-network pass
  over the exposure-ranked disagreement table, exposure summary, targeted
  public-map inspection queue, and decision-ledger summary. It isolates
  upazilas with active DGHS clinical rows and zero joined OSM health features,
  then keeps facility closure and absence language blocked. It is not human
  validation.
- The Bangladesh human-gated handoff matrix is a no-network pass over the
  source-repair clarification packet, possible same-facility review, priority
  and lower-priority name-conflict reviews, and zero-OSM observability summary.
  It consolidates open rows that still require source-owner clarification or
  human validation. It is not human validation.
- The Bangladesh human-validation worksheet is a no-network pass over the
  human-gated handoff matrix. It pre-fills public evidence and row-class
  minimum evidence rules while leaving every human-review decision field blank.
  It is not human validation.
- The Bangladesh AI closure audit is a no-network pass over the
  human-validation worksheet. It checks whether current public evidence plus
  blank human-review fields permit AI closure, same-facility reclassification,
  map-absence language, or coordinate correction. It is a keep-open audit, not
  validation.
- The Bangladesh facility-validation evidence ladder is a no-network pass over
  committed summary JSON files. It emits a 10-stage reader-navigation artifact
  from source-disagreement strata through the AI closure audit. It is not a
  statistical funnel and not validation.
- The Bangladesh source-repair public-evidence attachment is a no-network pass
  over the decision ledger and targeted-row confirmation packet. It attaches
  public DGHS profile and OSM API evidence to the four source-repair-first rows
  while keeping all rows open. It is not human validation.
- The Bangladesh source-repair official-coordinate evidence pass retrieves the
  four public DGHS profile pages and parses the embedded official map
  coordinate. It compares those coordinates with the pinned OSM candidate
  coordinates while keeping all rows open. It is not human validation.
- The Bangladesh source-repair public-explanation search checks live DGHS
  profile tabs, cached DGHS registry records, and official government health
  portals for public coordinate-source or coordinate-correction explanations.
  It sharpens the source-repair queue while keeping all rows open. It is not
  human validation.
- The Bangladesh source-repair correction-record follow-up checks targeted
  public DGHS registry, DGHS Health Dashboard, and government health portal
  pages for the Durgapur conflict and shared-coordinate Narayanganj rows. It
  keeps all targeted rows open. It is not human validation.
- The Bangladesh source-repair clarification packet converts those unresolved
  Durgapur and Narayanganj rows into source-owner questions and human-review
  prompts. It makes no external contact and keeps all targeted rows open. It
  is not human validation.
- The Bangladesh source-repair registry-vintage review joins the clarification
  packet to public DGHS profile update timestamps and correction-record status.
  It blocks closure, same-facility reclassification, and map-absence language.
  It is not human validation.
- Philippines ADM3 Open Buildings, NHFR code-resolution, and OSM-health context
  outputs are generated by the Python drivers in `scripts/`.
- Philippines poverty context now uses the owner-manually downloaded official
  PSA 2023 city/municipality SAE Excel at
  `public-service-data-quality/.cache/psa-phl-2023-sae-with-psgc-nohuc.xlsx`,
  plus PSA OpenSTAT direct estimates for HUC/direct-estimate rows.

No missing poverty value is imputed. Missing rows are explicitly marked
`no_poverty_table_match` when the official SAE workbook is present.

Run commands from the repository root.

Required for the site and gates:

```bash
node --version

```

Required for the PSDQ Python pipelines:

```bash

```

The lightweight poverty-context path uses `pandas`, `requests`, and `openpyxl`
when the Excel source is present. The full Open Buildings and road-context
paths also use `numpy`, `shapely`, `pyogrio`, `geopandas`, and `scikit-learn`.
